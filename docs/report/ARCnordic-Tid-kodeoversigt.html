1. Resumé

ARCnordic Tid er et PSA-system (tid, projekter, budget, godkendelse, fakturering, udlæg, fravær og flex, ressourceplanlægning, løneksport og rapportering) bygget som en ren genimplementering. Systemet er bygget i faser: M0 fundament, M1 tidsregistrering og godkendelse, M2 fakturering og perioder, M3 drift (udlæg, ressourceplan, dashboard, Outlook, analyse), M4 løneksport og import, samt rettelser efter kodegennemgang (adgangspolitik, privatliv, revisionsspor, GDPR, backup).

Teknologi: TypeScript overalt (Node 26, pnpm-monorepo), Next.js 16 og React 19 til web, Fastify 5 og Zod til API, Drizzle ORM og PostgreSQL 17 med row-level security, Python 3.12 og FastAPI til analyse. Biome (lint og format), Vitest, pytest og Playwright til test. Alt kører lokalt i Docker (D-017); driftsforslag ligger i docs/operations.md.

Designprincipper: forretningsregler er rene funktioner i domænelaget; alle eksterne systemer sidder bag adaptere og er slået fra som standard; al adgangslogik bor ét sted (AccessPolicy); hver fil har en forklarende header og hver eksporteret funktion en JSDoc/docstring, håndhævet automatisk.

2. Arkitektur

Koden er et monorepo med tre apps og fire pakker. Afhængigheder går kun nedad i diagrammet: domænet kender ingen andre lag, og web-appen taler kun med API'et via HTTP.

apps/web — Next.js (brugerflade)Sider pr. skærm (app/(app)/…), genbrugelige komponenter, i18n (dansk/engelsk). Viser kun handlinger, som serverens rollematrix tillader (kapabiliteter fra /me).
HTTP + session-cookie + CSRF-header
apps/api — Fastify (GRASP Controller + services)routes/: validér (Zod) → tjek adgang (requireCapability) → kald service → svar. services/: arbejdsgange (godkendelse, fakturaer, løn, GDPR …). Baggrundsjob: outbox, påmindelser, opbevaringsfrist.
funktionskald
packages/domain — forretningsregler (Information Expert)Rene funktioner: normtid, flex, ferie, satser, faktureringsforslag, nøgletal, løn, import, GDPR og AccessPolicy. Ingen I/O → hurtige, sikre tests.
packages/db — Drizzle + PostgreSQLschema.ts (alle tabeller), migreringer, RLS pr. virksomhed via withTenant(), audit-skriver, transaktionelle arbejdsgange (bogføring, perioder).
packages/integrations — adaptere (Polymorphism / Protected Variations)e-conomic (regnskab) og Microsoft Graph (kalender). Interfaces gør dem udskiftelige; slået fra uden konfiguration.
apps/analytics — Python FastAPI (skrivebeskyttet)Nøgletal, Excel og Power BI-datasæt via en databaserolle med kun SELECT. Formlerne spejler kpi.ts og testes med samme eksempler.

En request fra start til slut — "gem en celle i ugesedlen"

  1. Brugeren skriver 7,5 i en celle → week-grid.tsx sender PUT /api/v1/timesheet/entries med CSRF-header.
  2. auth/plugin.ts slår sessionen op (kun hash gemmes), indlæser roller og ekstra rettigheder og afviser manglende CSRF.
  3. routes/timesheet.ts validerer body med Zod og kalder saveCell() i services/timesheet.ts.
  4. Servicen henter data i en transaktion med app.tenant_id sat (RLS), og kalder domænets validateEntry(): 24-timers-grænse, 0,25-trin, lukket periode, påkrævet kommentar.
  5. Gemmer rækken; projektleder-stemplet nulstilles, hvis rækken ændres. Fejl kastes som AppError og oversættes centralt til { error: kode }, som web-appen viser på dansk.

    if (hasRole(this.roles, ...rule.roles)) return true;

4. Clean code — konventioner

  • Én sandhed pr. regel. Rollematrix (access.ts), beløbslinjer (isAmountLine), nøgletal (kpi.ts + Python-spejl testet med samme eksempler).
  • Enheder er heltal. Penge i øre, timer i centitimer (7,5 t = 750), procent i basispoint (81,08 % = 8108). Ingen kommatal i beregninger → ingen afrundingsfejl. Datoer er lokale ISO-datoer i Europe/Copenhagen.
  • Dokumentation håndhæves. scripts/check-docs.mjs kræver header i hver fil og JSDoc/docstring på hver eksport (TypeScript og Python) — del af pnpm check, pre-commit-hook og CI.
  • Navne fortæller hvad. Funktioner er verber (saveCell, exportPayroll), regler er navneord (retentionCutoff). Fejlkoder er maskinlæsbare (period_closed) og oversættes i UI.
  • Små, tynde lag. Ruter er korte; arbejdsgange i services; regler i domænet. Ingen forretningslogik i React-komponenter ud over visning.
  • Sikker som standard. Integrationer, mail og kalender er slået fra uden konfiguration; dev-login kan aldrig være slået til i produktion.
  • Automatisk formattering og lint (Biome) — ingen stilkampe i code review.

5. Sikkerhed og adgangsstyring

  • Login: uigennemsigtige session-tokens i httpOnly-cookie (kun SHA-256-hash gemmes), CSRF-token på alle ændringer, rate limit på login. Microsoft Entra ID (OIDC + PKCE) er bygget, men slået fra lokalt.
  • Virksomhedsadskillelse: PostgreSQL row-level security med en ikke-ejer app-rolle; hver forespørgsel kører med app.tenant_id sat. Analysetjenesten har sin egen rolle med kun SELECT.
  • Uforanderlighed: bogførte fakturaer er låst af database-triggers; revisionssporet (audit_log) kan kun indsættes i — app-rollen har ikke UPDATE/DELETE.
  • Funktionsadskillelse (D-025): Admin konfigurerer, Økonomi bogfører, krediterer, lukker perioder og eksporterer løn.
  • Privatliv (OQ-21): sygdom vises som "Fravær" uden kommentar for alle andre end medarbejderen, lederen og Økonomi — i ugevisning, rapporter og analyse.

6. Data og privatliv (GDPR)

  • Dataudtræk: Admin → Medarbejdere → "Hent alle persondata" giver én JSON-fil med alt om personen og intet om andre (exportPersonalData).
  • Sletning af fratrådte: "Slet personoplysninger" pseudonymiserer navn, e-mail, initialer og lønnummer, fjerner kommentarer og sletter ikke-bogføringsdata. Bogføringsdata bevares i 5 år efter regnskabsåret. Blokeres, hvis personen er aktiv, projektleder på aktive projekter eller leder for andre (erasePerson, erasureBlockers).
  • Deaktivering logger ud med det samme (sessioner og kalender-tokens slettes).
  • Natligt job sletter udløbne sessioner/tokens og logs ældre end 13 måneder og rapporterer bogføringsdata ud over fristen (sletning af regnskabsdata er en bevidst handling efter aftale med revisor).
  • Fortegnelse: docs/gdpr/processing-inventory.md.

Drift og backup

Lokalt tages en backup dagligt ved opstart (14 gemmes) og ved nulstilling; gendannelse er verificeret. Forslag til produktion (Azure EU, administreret PostgreSQL med point-in-time restore, Key Vault, Blob Storage, Microsoft 365-mail) og flytning ud af OneDrive står i docs/operations.md.

8. Vedligeholdelse — sådan tilføjer man en funktion

  1. Regel først: skriv beregningen som ren funktion i packages/domain/src/<emne>.ts med JSDoc og et eksempel, og en test med tal fra specifikationen.
  2. Data: tilføj tabel/kolonne i packages/db/src/schema.ts → drizzle-kit generate; nye tabeller med tenant_id får RLS via skabelon-migreringen (RLS-testen fejler ellers).
  3. Arbejdsgang: service-funktion i apps/api/src/services/; skriv til revisionssporet ved ændringer af økonomiske data.
  4. Adgang: tilføj en kapabilitet i AccessPolicy, hvis handlingen er ny; brug requireCapability i ruten og can(me, …) i web.
  5. Rute: tynd Controller med Zod-skema i apps/api/src/routes/; registrér i app.ts.
  6. UI: side under apps/web/src/app/(app)/, tekster i i18n/da.ts og en.ts.
  7. Test og dokumentation: API-test (rul tilbage, hvis den skriver), evt. E2E; beslutning i docs/decisions.md; kør pnpm check; generér denne rapport igen.

13. Kendte begrænsninger og anbefalinger

Kræver beslutning hos ejeren

  • Hosting (OQ-04) — forslag i docs/operations.md; indtil da kun lokal test med opdigtede data.
  • Flyt arbejdskopien ud af OneDrive (OQ-01) — trin-for-trin i docs/operations.md §4.
  • Åbne fagspørgsmål — flexloft, ferieoptjening, kilometersatser og moms (OQ-36), nummerserier, lønudbyder (OQ-08), offentlige kunder/OIOUBL (OQ-32), opbevaringsfrist og regnskabsår (OQ-39). Systemet kører på standardvalg indtil da.

Bevidste forenklinger

  • Løneksport er generisk CSV; adaptere til Danløn/DataLøn/Zenegy kommer, når udbyderen er valgt.
  • Persondata-udtræk er én JSON-fil (spec nævner ZIP med JSON+CSV).
  • Revisionssporet er append-only men endnu ikke hash-kædet (spec R2 foreslår kæde for manipulationssikring).
  • Kalender-tokens fornyes ikke automatisk (ingen refresh-tokens gemmes) — brugeren logger ind med Microsoft igen.
  • Bogføringsdata ud over 5 år rapporteres, men slettes ikke automatisk.

Gode næste skridt

  • Entra ID med automatisk oprettelse og gruppe → rolle (OQ-10), så roller ikke vedligeholdes to steder.
  • Projektskabeloner med faser fra ydelsesbeskrivelsen (OQ-23).
  • Mobil/PWA til tidsregistrering på byggepladsen.
  • API-tokens (spec R10), så Power BI kan opdatere automatisk.
